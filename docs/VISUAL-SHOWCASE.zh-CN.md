# 产品主页 Visual Showcase 规范

**[English](VISUAL-SHOWCASE.md)** · 简体中文

状态：2026-11-04 提案。本文规范**产品站点的展示与证据**，不代表任何产品已经发版、验收通过或界面定型。产品自己的行为契约、验收记录、Release 和用户手册仍是权威来源。

## 目标

一个初次访问的人应在前一到两屏看懂：这是什么产品、能解决什么事、怎么操作、现阶段能用到什么。官网可以采用图片和交互视觉；详细手册仍以可维护的文字说明为主。

## 按成熟度选择视觉材料

| 产品阶段 | 推荐材料 | 应标注 |
| --- | --- | --- |
| 架构 / Alpha | 真实输入、边界、输出或模块之间的架构/流程示意 | “概念工作流程 / 架构图，非软件截图” |
| UI 大幅重构 | 已核对版本的局部真实界面；否则使用明确标注的场景示意 | “开发预览，界面可能变化” |
| 安装包和 UI 已稳定 | 从指定发布构建采集的真实截图，说明平台和版本 | “在 平台 / 版本 下采集” |
| 动态交互是产品核心 | 真实已打包构建的静音短演示，配字幕和静态回退 | “在 平台 / 版本 下录制” |

仓库里存在旧截图不等于它仍准确。CSS 模拟器、概念设计、仿真 ECU 证据、未实现动画、规划中的功能，绝不能伪装成实机运行截图。示意图标注要在视觉附近，不应只藏在 alt 文本里。不能虚构性能、精度、完成时间或客户口碑。

## 推荐页面结构

1. 产品名、一句容易理解的价值说明、实际可用状态、准确的下载/源码入口。
2. **产品如何工作**：一幅清晰的截图、工作流程、架构示意或输入输出对照；同时注明证据等级。
3. 三个具体使用场景，强调成果而非堆砌图标和形容词。
4. 平台与限制、五分钟上手、恢复/帮助/隐私和源代码或安装包入口。

统一排版、间距和视觉节奏，不强迫所有产品使用相同的三卡片示意。消费类软件要展示真实使用感受，工程类工具要展示实际数据和可核对证据，框架项目要解释架构并给出简短可运行实例。

## 素材维护与发布

- 原图或可复现的生成输入存放在所属仓库；必要时记录对应提交、采集环境、许可和维护责任人。
- 截图使用无敏感信息的固定测试数据、干净的首次启动状态与可重复命令，不能泄露个人文件、令牌或设备信息。
- 自动生成的是**候选截图**，不能自动视为可发布证明。必须核对 GUI、语言、平台限制、可读性、无障碍和图片体积后才能合并。
- 重要 UI 调整或发版后，重新采集并更新平台/版本，或退回正确标注的流程示意；不得默默保留错版图片。
- 图像须合理压缩、声明尺寸；首屏之外可懒加载。不要让主页最大视觉区域产生过多加载延迟或布局抖动。
- 中英文、明暗主题、手机宽度、键盘焦点、对比度、alt、图注、减少动态效果和视频回退都必须检查。

## 验收清单

- [ ] 新访客能在前两屏说明产品是什么、主要操作是什么。
- [ ] 每张图都对应明确版本或醒目标记为概念示意。
- [ ] 不暗示未交付平台、开放购买、硬件精度或未经验证的外部服务能力。
- [ ] 没有重新使用已经过时的截图。
- [ ] 中英文图注和限制一致；alt 具有语义。
- [ ] 在浏览器核查桌面、移动、亮暗主题和减少动态效果。
- [ ] 合并后检查公开 URL、资源加载和 Pages 部署。
- [ ] 声称展示真实已打包 UI 时，相关平台/构建应有完整原生验收依据。
